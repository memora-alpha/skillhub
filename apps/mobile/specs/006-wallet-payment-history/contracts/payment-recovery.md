- Mapping retained: same owner/operation/key/body returns same Payment; changed body409. - Fresh keys blocked for current-owner CREATED/PENDING/REVIEW, any legacy PAYOS identity-less Payment, global unresolved foreign channel, pause or provider unavailable. Same-identity replay precedes fresh policy; provider-enabled and amount checks still precede replay (create:39–80; policy service:24–66).
- Live actor/user lock + Serializable transaction protect the claim/reservation. Backend retry on DB conflicts is not a mobile HTTP retry policy. Worker uses stored orderCode/current channel after commit; it does not recover lost mobile keys.
- Authenticated creation-policy gives current own blocker or safe global reason, no reservation/version/horizon. Owner detail/list are reads independent of create. List is checkout-backed, not proof of absence of every Payment.
- Both mapping AND Payment identity lost: if unpaused/no other blocker, BE can treat key as new. No detector, automatic reconstruction, financial repair or REVIEW replacement-clearance API. Known restore/unknown previous attempt must remain blocked/support-required. Never conclude no transfer from404/empty list.

## Client intent and persistence rules

Approved D2 remains native-first separate financial SecureStore, environment+owner namespace, WHEN_UNLOCKED_THIS_DEVICE_ONLY, one JS writer/coordinator and synchronous claim. Web creation stays unavailable; no plaintext/memory fallback. Do not reuse auth-token-store, query cache or credentials storage for financial correlation.

Freeze owner/environment, stable key, canonical `{paymentAmountVnd,gateway:"PAYOS"}` and conservative DISPATCH_MAY_HAVE_OCCURRED marker before awaiting storage/network. Write + validate read-back before POST; storage/corruption/capacity failures block network. Store optional paymentId after valid response; failed ID persistence does not turn Payment into failure or permit another POST/key. Session generation is RAM-only. No QR, provider payload, balance/history, tokens or credentials persisted. Budget<2KiB is design scope, not a backend/SecureStore guarantee.

Use shared authenticated HTTP with AbortSignal and replayAfterRenewal:false; no automatic create/replay on renewal/reconnect/focus/foreground or timers. Explicit same-key/body replay is an intentional recovery action, not a new top-up. PAYMENTS_ENABLED=false503 still blocks replay; pause alone with provider enabled does not. A true policy snapshot does not override a retained unknown intent or known incident.

Policy/409 recovery follows the local known ID or an explicit authenticated policy GET → current own blocker GET. Existing shared errors discard details; do not assume details.existingPaymentId is available without new owned/tested infrastructure. No policy ID is proof that amount/time matched a lost intent. Missing/unavailable policy leaves the block intact.
