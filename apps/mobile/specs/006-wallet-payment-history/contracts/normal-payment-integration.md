## Current source

- `src/features/wallet/context/account-capabilities.ts` enables independent owner Payment status reads on native/web, native create/recovery on iOS/Android, and no standalone quote capability. Web create/recovery remains unavailable; there is no browser or RAM storage fallback for account requests. `noWalletCapabilities` remains an inert default.
- `hooks/use-owner-payment-create.ts` binds the existing authenticated client, normalized API environment, current owner/session coordinator, SecureStore opener and UUID generator. `context/payment-create-session.ts` shares one model per environment and uses a focus lease so late blur cleanup cannot cancel the next screen. Background/blur detaches QR and aborts work; foreground/focus resumes only reads/restoration, never POST/replay. Strict effect reactivation re-registers cleanup and releases obsolete pending leases.
- `views/topup-screen.tsx` now renders the real account-mode `PaymentCreatePanel`, not the legacy preparation model. Draft → advisory policy GET → review → explicit Confirm → verified durable claim → POST uses the existing coordinator. Estimates remain distinct from backend-confirmed quote/expiry. Explicit confirm/replay navigates once to Payment only while the same route-focus lease/session remains current. Back preserves draft/identity. Existing unresolved requests have an explicit continuation; another top-up requires verified terminal resolution/cleanup with no recovery warning.
- `views/payment-screen.tsx` shows the retained request, confirmed quote, local QR renderer and backend outcome. It accepts no financial fields from URL. Opening the route without an intent only offers top-up; no create occurs on mount. Same-version QR suppression, REVIEW/unknown and storage-warning behavior remain intact. A missing ID permits only explicit same-key replay; a known ID is read again. Initialization/storage verification errors allow explicit restoration without a POST. Total-loss support-stop offers no replacement intent.
- `views/payment-status-screen.tsx` keeps owner UUID-only reads independent of create/storage/QR. The source capability is now enabled. Normal Payment and status reuse the independent PAID Wallet/History refresh coordinator; read failure cannot downgrade PAID or add Credit at the client. Terminal durable cleanup occurs in the create coordinator when the retained request is resumed/read; the independent status route does not require opening financial storage.
- Shared Input/Button/theme typography and orange amount presets are reused. Preview remains synthetic, labeled and isolated. Six public routes stay thin; no backend/shared package/dependency/lockfile change.
